Updates: 20260110

New APIs:
- Promotions CRUD: GET/POST/PUT/DELETE /promotions (admin: all, cashier: read)
- Addresses CRUD: GET/POST/PUT/DELETE /addresses (admin only)
- QR Image: GET/PUT /assets/qr-image (admin: read/write, cashier: read)

Bills:
- Payment: PUT /bills/:id/payment (accepts paymentMethod/paymentRef, sets status=completed)
- Cancel: PUT /bills/:id/cancel (status=new/hold → cancelled)
- Delete: DELETE /bills/:id (admin only, cascade delete)
- Removed: PUT /bills/:id/checkout
- Status validation: All modifications (add/remove items, discounts, payment) require status="new"

POS:
- Added pos_secret and is_active fields
- Endpoints: PUT /pos/:id/toggle-activate, GET/PUT /pos/:id/secret
- Login now validates pos_secret and is_active

Schema:
- promotion_master: code, details, unit (THB/%), amount
- address_master: FK cascade delete, part_code/store_id NOT NULL
- pos_setting: pos_secret, is_active

Permissions:
- Added: bills.delete, promotions.*, addresses.*, qr_image.*, pos.secret

Updates: 20260120

Bills:
- GET /bills: Added date filtering (query params: `date`, `date_from`, `date_to`)
  - Formats: ISO string (RFC3339) or yyyy-mm-dd
  - Default: Current date in UTC+7 (00:00 to 23:59) if no params provided
  - Use case: Frontend dashboard queries with date filtering
- Inventory management: Add/remove items, cancel, and delete operations now update inventory
  - Add item: Checks sufficient inventory at address_master, atomically reduces qty before adding to bill
  - Remove item: Returns inventory to address_master
  - Cancel bill: Returns all items' inventory to their addresses
  - Delete bill: Returns inventory (if status != "completed"), prevents deletion of completed bills

Repository:
- BillRepository.List(): Added optional dateFrom, dateTo parameters
- Dynamic SQL query building with date filtering on created_at field

Documentation:
- Updated Postman collection with date filtering parameters
