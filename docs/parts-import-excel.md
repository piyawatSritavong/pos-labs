# เพิ่มสินค้าด้วยไฟล์ Excel

ปุ่ม **เพิ่มด้วยไฟล์** ในหน้าสินค้า (Back office → สินค้า) รับไฟล์ Excel ที่กรอก
ตามเทมเพลต แล้วสร้างสินค้าทั้งไฟล์เข้า **คลังหลัก (`main`)** ในครั้งเดียว

## เทมเพลต

ดาวน์โหลดจากปุ่มในหน้าต่างอัปโหลด หรือใช้สำเนาที่อยู่ใน repo:
`docs/templates/เทมเพลตเพิ่มสินค้า.xlsx`

ไฟล์ต้นทางที่ backend ฝังไว้และส่งให้ดาวน์โหลดคือ
`backend/internal/partsimport/parts_import_template.xlsx` — สร้างใหม่ด้วย

```
python3 scripts/generate-parts-import-template.py
```

เทมเพลตมี 2 ชีต: ชีตแรก (`สินค้า`) คือชีตที่ระบบอ่าน มีแค่หัวคอลัมน์ในแถวที่ 1
ส่วนตัวอย่างอยู่ในชีต `ตัวอย่าง` ซึ่งระบบไม่อ่าน — อัปโหลดเทมเพลตเปล่าจึงไม่
สร้างสินค้าตัวอย่างติดมาด้วย

## คอลัมน์

| คอลัมน์ | field ใน database | ว่างได้ไหม |
|---|---|---|
| ชื่อสินค้า * | `part_master.name` + `name_th` | ต้องกรอก |
| ราคาขาย * | `part_master.price` | ต้องกรอก |
| ต้นทุน | `part_master.cost` | ว่าง = 0 |
| จำนวนที่รับเข้าคลังหลัก | `address_master.qty` (store `main`) | ว่าง = 0 |
| รหัสสินค้า | `part_master.code` | ว่าง = ออกให้อัตโนมัติ `P0001`, `P0002`, … |
| บาร์โค้ด | `part_master.bar_code` | ว่าง = ใช้รหัสสินค้า |
| หน่วย | `part_master.unit_id` | ว่าง = `pcs`; ค่าที่ไม่มีใน `unit_master` จะถูกเก็บเป็น NULL |
| ราคาขายขั้นต่ำ | `part_master.min_price` | ว่าง = 90% ของราคาขาย |
| ชั้นวาง | `address_master.shelf` | ว่างได้ |
| รายละเอียด | `part_master.details` | ว่างได้ |

ระบบจับคู่คอลัมน์จาก**ข้อความหัวคอลัมน์** ไม่ใช่ตำแหน่ง จึงสลับลำดับหรือเพิ่ม
คอลัมน์ของตัวเองได้ แต่ห้ามแก้ข้อความหัวคอลัมน์

## ข้อจำกัด

- นามสกุล `.xlsx` เท่านั้น
- ขนาดไม่เกิน **2 MB** — ไฟล์ 1,000 แถวที่ Excel บันทึกอยู่ราว 150–300 KB จึงเหลือ
  ที่ว่างพอสำหรับการจัดรูปแบบที่ผู้ใช้ใส่เพิ่ม
- ไม่เกิน **1,000 รายการต่อไฟล์**
- ทั้งไฟล์สำเร็จหรือไม่สำเร็จพร้อมกัน — ถ้ามีข้อผิดพลาดแม้แต่บรรทัดเดียว จะไม่บันทึกอะไรเลย
- ชื่อสินค้าซ้ำกันเองในไฟล์ หรือซ้ำกับสินค้าที่มีอยู่แล้ว จะถูกปฏิเสธ — คลังหลักถือ
  หลัก 1 ชื่อ = 1 สินค้า (ดู `deploy/supabase-catalog-rebuild-20260808.sql`)

ค่าจำกัดทั้งหมดอยู่ที่ `backend/internal/partsimport/import.go` และหน้าจอดึงมาแสดง
จาก `GET /parts/import/limits` เพื่อไม่ให้ตัวเลขสองฝั่งหลุดจากกัน

## API

| Method | Path | สิทธิ์ |
|---|---|---|
| GET | `/parts/import/template` | ไม่ต้องยืนยันตัวตน (ไฟล์เปล่า ไม่มีข้อมูลธุรกิจ) |
| GET | `/parts/import/limits` | `parts:write` |
| POST | `/parts/import` (multipart, field `file`) | `parts:write` |

การตอบกลับของ `POST /parts/import`:

- `201` — `{"created": n, "codes": [...], "storeId": "main"}`
- `400` — ไฟล์ไม่ใช่ `.xlsx` / อ่านไม่ได้ / หัวคอลัมน์ไม่ครบ
- `413` — ไฟล์ใหญ่เกินกำหนด
- `422` — `{"error": "invalid_rows", "rows": [{"row": 3, "column": "ราคาขาย", "message": "..."}]}`
- `409` — `{"error": "conflicting_rows", ...}` ชื่อหรือรหัสซ้ำกับสินค้าในระบบ

## หมายเหตุการพัฒนา

ตัวอ่าน `.xlsx` เขียนด้วย standard library ของ Go ล้วน
(`backend/internal/partsimport/xlsx.go`) ไม่ได้ใช้ไลบรารีสเปรดชีตภายนอก —
รูปแบบไฟล์เป็นของเราเอง และชีตเป็นตารางข้อความ/ตัวเลขธรรมดา
